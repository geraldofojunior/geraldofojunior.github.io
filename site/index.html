I build memory systems for AI.

My current work is on high bandwidth flash (HBF), an emerging 3D-stacked NAND flash memory that puts terabytes of capacity next to the accelerator. With HBF, a single accelerator or a small node can serve larger language models.

Before Huawei, I did my Ph.D. and a postdoc in Onur Mutlu’s SAFARI Research Group at ETH Zürich. I worked on processing-in-memory (PIM) across the stack, from computing inside DRAM chips to the programming models and compilers that make it usable.

Research

Moving data between processors and memory limits both performance and energy efficiency. My work has three threads: memory systems for AI, understanding data movement, and computing inside memory. With colleagues, I also work on DRAM reliability and security, near-data processing for applications, and programming and system support for PIM.

Memory systems for AI

LLM inference is increasingly limited by the memory capacity of the accelerator rather than by its compute. At Huawei, I work on adding that capacity with high bandwidth flash.

  1. FLINTHPCA 2027

    Stores LLM weights in HBF, next to HBM. A hardware burst-buffer controller coalesces and pipelines HBF reads, using the existing NAND flash buffers, to keep bandwidth high. A phantom-plane refresh mechanism moves refresh off the critical inference path, and a read-only flash translation layer maps the weights to HBF locations with a compact table.

    PaperLetter, IEEE CAL 2026

Related Bulk bitwise operations inside NAND flash (Flash-Cosmos, MICRO 2022), processing-in-DRAM for neural network inference from the edge to the cloud (IEEE Micro 2022), the machine learning inference bottlenecks of Google’s edge models (Mensa, PACT 2021), and neural network computation inside a Hybrid Memory Cube (NIM, ARC 2017).

Understanding data movement

Before changing the hardware, I measure where time and energy go, in real applications and on real systems.

  1. DAMOVIEEE Access 2021

    A methodology and benchmark suite for data movement bottlenecks. We characterized 77K functions across 345 applications, classified them by the sources of their data movement, and selected 144 of them as the first open-source benchmark suite for main-memory data movement studies. A case study with near-data processing shows which fix suits each kind of bottleneck.

    PaperCodeTalk

Related Methodologies and tools for PIM (ISVLSI 2022), a characterization of UPMEM, the first commercial PIM system (IEEE Access 2022), and an experimental study of emerging non-volatile memory for more memory capacity in consumer devices (IEEE Access 2023).

Computing inside memory

Processing-using-DRAM computes with the DRAM arrays themselves, so the data never leaves the memory chip. SIMDRAM, MIMDRAM, Proteus, and PipeDRAM each remove a limitation of the one before.

  1. SIMDRAMASPLOS 2021

    Builds arbitrary operations from in-DRAM majority and NOT, and runs them one bit at a time across thousands of DRAM columns at once. With 16 DRAM banks, it provides 88× the throughput of a CPU and 5.8× that of a high-end GPU, on average across 16 operations.

    PaperLecture

  2. MIMDRAMHPCA 2024

    Lets different segments of a DRAM row run different operations at the same time, using fine-grained DRAM access: a multiple-instruction multiple-data model inside each subarray. Compiler passes map ordinary loops onto it. It provides 34× the performance and 14.3× the energy efficiency of SIMDRAM, on average.

    PaperCode

  3. ProteusICS 2025

    Lowers the bit precision of each operation at run time to what its values need. It also runs independent steps across several DRAM arrays at once, and picks the data representation and arithmetic algorithm for each instruction. With a single DRAM bank, it provides 10.2× the performance per area of SIMDRAM and 8.1× lower energy, on average.

    PaperCodeTalk

  4. PipeDRAMMICRO 2026

    Computes directly on data in the horizontal layout that CPUs use, so data is never transposed. The memory controller reorganizes the bits inside each memory request, and a pipelined execution model overlaps bit-dependent and bit-independent operations across the DRAM array. It provides 11.8× the performance of both SIMDRAM and MIMDRAM, and 80.4× that of Proteus, on average.

    PaperCode

  1. DaPPAICCD 2026

    A programming framework for these systems. Programmers express a computation once, with data-parallel patterns and a dataflow interface, and DaPPA’s back-ends generate the data orchestration for a real near-memory system (UPMEM) and the multi-level tiling for processing-using-DRAM. On UPMEM, it is 1.6× faster than hand-tuned code, with 95% fewer lines of code, on average.

    PaperCode

Related Boolean logic (HPCA 2024) and true random numbers (ICCD 2025) in real DRAM chips, lookup-table computing in DRAM (pLUTo, MICRO 2022), and an overview of recent advances in processing-in-DRAM (IEDM 2024).

With colleagues

  1. DRAM reliability and security

    Read disturbance (RowHammer) in real DRAM chips and defenses against it: Chronus, Variable Read Disturbance, Svärd, ABACuS, and RowHammer under reduced wordline voltage; and error profiling for on-die ECC with HARP. Chronus (HPCA 2025) received the 2026 Intel Hardware Security Academic Award.

  2. Near-data processing for applications

    Hybrid transactional and analytical databases (Polynesia), raw-signal genome analysis inside storage (MARS), stencil computations near the cache (Casper), and an overview of the field, A Modern Primer on Processing in Memory.

  3. Programming and system support

    Besides DaPPA: transcendental functions for PIM (TransPimLib), machine learning workloads on a real PIM system (ISPASS 2023), CPU-memory data movement in memory-centric systems (ALP), and performance prediction for near-memory computing (NAPEL).
